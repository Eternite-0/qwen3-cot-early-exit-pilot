# Requirements for a stronger follow-up run

This is a prospective recovery checklist based on training/dev audits, written before the agent read v6 quality results. It is not a claim that another experiment or 20k expansion has run. The current frozen predictions, data, weights and selection rules remain unchanged.

1. **Repair latent split isolation before producing text.** Enumerate/canonicalize task instances, rule graphs and template families; reserve disjoint buckets before rendering. Remove decorative case identifiers from every deduplication key. Check equality of exact parameters, graph canonicalizations and answer-preserving rewrites across train/dev/test. Fail data generation on overlap rather than just reporting it after training. Keep an independent externally sourced evaluation distinct from target-informed synthetic transfer.
2. **Make task and teacher coverage informative.** The current screened320 rows include only4 time/numeric items and36 rules items. Remove generator shortcuts such as always-feasible routing and trivial direct-edge reachability in a new version. Use executable task certificates to validate relevant reasoning operations. Literal coverage of numbers/capitalized symbols cannot certify free-form CoT and can reject valid intermediate arithmetic. Audit closure, final-answer accuracy and step validity separately; measure the consequences of rejection sampling by family/length/difficulty. Do not relabel the current lexical screen as logical verification.
3. **Verify algorithmic fidelity explicitly.** Retain the source paper version/formulas and seek an author-verified implementation. Check alpha/prefix/chat boundaries, response normalization, rollout-versus-loss dropout and the gradient of the on-policy outer expectation. Separate a full-gradient verified method, a stop-gradient KL surrogate and ordinary SFT in both names and comparisons. Do not infer that exact per-context vocabulary KL establishes complete objective-gradient fidelity.
4. **Match the scientific comparison budget.** Shared initialization/examples/order/teacher filtering are necessary but do not equalize trained tokens or FLOPs. Record rollout, student-forward, teacher-forward and target tokens and actual allocation time. Run a prespecified compute-matched comparison as well as update-matched comparison. Use the same answer formatting and no-think/chat boundaries for answer-only and corresponding trace controls where mathematically appropriate. Choose learning rates, training duration and stopping only on the new independent dev set. The current64-update, one-seed run does not establish an asymptotic method ranking.
5. **Resolve quality/readout/latency attribution.** Compare native and candidate-conditioned heads at each depth on every relevant backbone. Compare an exit with its own L28 under the same head and backend before attributing speed to fewer layers. Keep actual incremental stopper/head costs. Optimize the native serving prototype under a new numerical fixture/protocol, not by selectively removing slow current test requests. Never replace measured truncated-forward latency with a fraction of full-depth timing.
6. **Freeze a new adequately sized confirmation.** Current dev planning suggests thousands of items for a2pp paired non-inferiority claim, depending on the true disagreement/cluster variance. Re-estimate from the repaired independent dev data, account for multiplicity and desired power, and budget three training seeds when resources allow. A500-item, one-seed pilot cannot substitute for that confirmation. The original expansion gate remains MSD1 minus matched answer-only at least3pp with paired95% lower bound at least0; this note does not change it.
7. **Keep unmeasured claims separate.** AG News120 is a narrow classification regression check. Broad capability retention needs additional independent tasks. Generation interruption needs reliable prefix/action/outcome labels and a separately frozen replay protocol; current teacher traces do not provide those intervention labels. Steering and memory remain secondary ablations after the core comparison is validated.

Any follow-up requires a fresh timestamp directory, its own preregistration and measured GPU/storage budget. Already viewed v6/JevBench/pilot items remain diagnostics. No paid cloud resources or changes to shared environments/security are authorized by this checklist.
