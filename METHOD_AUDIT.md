# Implemented MSD-style pilot: correspondence and limits

Source: saved arXiv2607.22629v3 HTML/text, section3 equations1–4 and appendixA.3; no author-owned official implementation was verified. All statements here describe the saved script/checkpoints rather than claiming authors' exact code behavior.

- Same frozen Qwen3-1.7B initialization for teacher/student. Teacher parameters have requires_gradFalse, eval mode; no EMA or teacher updates. Student learns only LoRA projections.
- The teacher saw a recorded train-only trace prefix of floor(alpha*m) tokens, inside Qwen think delimiters. Full prefix restores the closing delimiter and no-think prompt suffix. At zero prefix this implementation keeps exactly the student's empty-think/no-think prompt; its initial KL=0 is a code sanity check, not a replication of paper alpha0 empirical behavior. Official chat-boundary implementation is unverified.
- Each microbatch samples fresh response IDs from the current student using eval mode, temperature1/top-p1/top-k0 and no sampling gradient. It then restores training mode. KL scoring therefore has active LoRA dropout .05, whereas rollout dropout is off. This discrepancy is part of the small LoRA pilot and must be considered when interpreting formula-level fidelity.
- The differentiated loss is the exact full-vocabulary sum q*(logq-logp_teacher) per sampled response position, summed over response tokens and averaged over instances. Teacher distributions are detached. Gradients flow through student q/logq at the sampled contexts. There is no derivative through discrete sampled IDs, no REINFORCE/score-function term for the sampling distribution, and no claim that the complete gradient of the outer expectation in equation1 was verified against author code. Treat this as a current-weight on-policy, full-vocabulary KL surrogate pilot, not a fully verified original-paper implementation.
- Ordinary answer-only and teacher-suffix methods use token-mean cross entropy, not KL. Their same examples/updates budget does not equalize tokens, loss normalization or FLOPs. Partial SFT proxy alpha0/.5 uses an open-think training prompt; alpha1 uses no-think and raw teacher solution IDs. All formal generation evaluation is no-think. The alpha1 raw solution has leading double-newlines in320/320 screened rows; answer-only uses canonical complete-chat tokenization. These formatting differences limit algorithm attribution for the SFT proxy grid.
- The320 screened traces have correct final labels and symbolic/numeric grounding; no logical proof of all steps or independent human trace audit exists. Time/numeric coverage is only4 rows. All adapters ran64 updates on the same first256 rows, but dev selection restored different16/32/64-step checkpoints; selected step and true exposure/compute must remain visible.

The historical grounding test is actually lexical atom coverage, not an executable logical derivation verifier. A dev-only audit (`teacher_lexical_screen_limitations.json`) demonstrates that correct derived arithmetic intermediates can be absent literally from the prompt/certificate and be rejected by this filter. Neither rejection nor acceptance is a trustworthy step-quality label. The accepted data and all frozen training/model selections remain unchanged; this is an additional validity limitation of the actual pilot.

The underlying task generator also failed strict latent-instance isolation after case_ref removal. Read README and the semantic/counterfactual audit. None of these limitations licenses test-guided prompt/weight/threshold changes. Preserve and report the actual pilot; future fidelity/data corrections need a fresh protocol/run and must not reuse current test feedback as an untouched evaluation.

Latency attribution also depends on the serving path. The native cached-candidate prototype retains full-position prefill logits to satisfy the unchanged numerical fixture; it is not an optimized production-backend lower bound. Trained heads avoid the vocabulary projection/candidate continuation, and generation has its own decode cost. Compare each fixed exit to its own backbone/readout L28 to isolate truncation; head-L28 versus generation is a readout/serving-path change, not a layer-saving result. Keep the frozen primary comparison and the separately disclosed attribution analysis distinct.
