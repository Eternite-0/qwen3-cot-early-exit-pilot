Train the same candidate-conditioned lightweight head as the prior engineering control at depths 2/4/8/12/16/20/24/28 for original, matched answer-only, and dev-selected MSD backbones. Use all 320 accepted train rows for every backbone, the original 300-row dev set, 8 epochs, batch 32, AdamW LR .001/weight decay .0001, gradient clip 1, per-depth initialization seed `20281028+depth`, identical per-epoch orders, and dev accuracy checkpoint selection with earliest tie. The head consumes a pre-final-RMSNorm block state and candidate-label embedding; it has no candidate index-specific parameters. Order-permutation tests verify equivariance. This is a new trained head diagnostic and is distinct from an untrained intermediate LM head.

Fixed exits must terminate after their requested decoder block. Native readout scores the exact full candidate string and terminal EOS using the existing final norm/LM head, and reuses one prefill/KV for all candidates. Scores are sequence log-likelihood sums, then normalized across allowed candidates. This conditional candidate distribution is a synthetic-task scoring mode, not a benchmark-specific official score or an unconstrained-generation schema result. Trained heads use one prefill. Full generation, native candidate scoring, and trained-head decisions are measured and labeled separately.

LoRA adapters are merged into a private in-memory BF16 copy for all new inference/readout timing, eliminating adapter-dispatch overhead; no shared or saved original weights are modified. Merge equivalence is checked on dev fixtures and any changed predictions/precision error are recorded. Training checkpoint selection used the unmerged adapter; no selection changes follow this precision audit.

Use paired dev differences for a transparent approximate sample-size calculation; insufficient power must remain a limitation.
